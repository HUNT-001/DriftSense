# Docs templates: how numbers get into the docs

Judges may reject entries that misrepresent results. So **no one types a number
into a submission doc**. Every measured number is pulled from a validated
`results/**/*.json` file (`driftsense.contracts.ResultsFile`) by
`scripts/render_docs.py`, and `scripts/check_claims.py` proves that every number
in the generated docs traces back to that JSON.

```text
results/**/*.json ──(ResultsFile / plain JSON)──► render_docs.py ◄── docs/templates/<NAME>.md.j2
                                          │
                                          ▼
                            docs/<NAME>.md  (GENERATED header + provenance markers)
                                          │
                                          ▼
                                   check_claims.py  (make claims, CI job "claims")
```

## Files and commands

| What | Where |
|---|---|
| Templates | `docs/templates/<NAME>.md.j2` renders to `docs/<NAME>.md` |
| Root docs | `docs/templates/README.md.j2` and `docs/templates/SUBMISSION.md.j2` render to the repo-root `README.md` / `SUBMISSION.md` (next to `--readme`), only with `--include-readme` (off by default, so a hand-written root file is never clobbered). Once a root file carries the GENERATED header, both scripts re-render it automatically. |
| Partials | names starting with `_` (e.g. `_macros.md.j2`) are never rendered on their own; use them with `{% include %}` / `{% import %}` |
| Render | `python scripts/render_docs.py` (`make docs`) |
| Staleness check | `python scripts/render_docs.py --check` exits 1 if any rendered file differs from disk |
| Claims check | `python scripts/check_claims.py` (`make claims`) |
| Draft with gaps | `python scripts/render_docs.py --allow-missing` writes visible `⟨missing: results/x.json#metric⟩` placeholders; `check_claims` fails on them, so never commit a draft |

Rendered files start with
`<!-- GENERATED by scripts/render_docs.py from docs/templates/X.md.j2 — do not edit; numbers come from results/**/*.json -->`.
Edit the template, never the generated file.

## The three printing functions

A results **key** is the path under `results/` without `.json`:
`"accuracy/g2"` means `results/accuracy/g2.json`.

### `m(key, metric, fmt=None, ci=false, label=true)`: a metric value

```jinja
{{ m("accuracy/g2", "speedup") }}
{{ m("sealed/finfet", "top1_success", fmt="pct", ci=true) }}
{{ m("accuracy/g2", "top1_success", fmt="pct", label=false) }}
```

renders (marker shown; it is invisible on GitHub and in pandoc HTML/PDF):

```text
12.3× [DEV]<!--src:results/accuracy/g2.json#speedup fmt=x-->
47.5% (95% CI 40.1–54.9%) [SEALED]<!--src:results/sealed/finfet.json#top1_success fmt=pct ci-->
47.5%<!--src:results/accuracy/g2.json#top1_success fmt=pct nolabel-->
```

### `n(key, metric, label=true)`: the sample size `Metric.n`

```jinja
{{ n("accuracy/g2", "speedup") }}   →  400 [DEV]<!--src:results/accuracy/g2.json#speedup field=n fmt=int-->
```

### `meta(key, field, fmt=None)`: file metadata (no label)

`field` is one of `git_sha`, `created_at`, `dataset`, `protocol_sha256`, `name`,
`produced_by`, `schema_id`, or `env.<EnvInfo field>` (`env.instance_type`,
`env.opencv`, `env.python`, `env.numpy`, `env.platform`, `env.arch`, `env.cool`).
`meta(key, "created_at", fmt="date")` gives just the date. A null field
(e.g. `protocol_sha256` on a DEV file) is an error.

```jinja
{{ meta("bench/cool_bench", "env.instance_type") }}  →  c8g.4xlarge<!--src:results/bench/cool_bench.json#@env.instance_type-->
```

### `q(relpath, jsonpath, fmt=None)` and Person A's placeholder grammar

Person A's report pages use one placeholder grammar, which any template may mix
with `m()`/`n()`/`meta()`:

```jinja
{{ sealed/v1.json | metrics['top1.pooled'].value | pct }}%
{{ sealed/decisions.json | rules.D7_false_confident.pass }}
{{ sealed/disclosures.json | disclosures.2.id }}
`{{ sealed/decisions.json | overall_pass }}`
```

- `relpath` is the path under `results/` **including** `.json` (a leading
  `results/` is accepted). It may be a `ResultsFile` or a **plain JSON document**
  (see below), so both `metrics[...]` paths and top-level keys resolve.
- `jsonpath` is dotted; segments containing dots use bracket form
  (`metrics['top1.pooled'].value`, `["..."]` also works); list indexes are
  numeric (`disclosures.2.what` or `disclosures[2].what`).
- `fmt` prints the **bare number**; the template writes `%`, `×` or ` ms` itself:

| fmt | Output | fmt | Output |
|---|---|---|---|
| (none) | verbatim: strings as-is, `true`/`false`, integral floats without `.0`, other floats as `repr` | `x1` | one decimal |
| `pct` / `pct0` / `pct2` | ×100 with one / zero / two decimals (not multiplied when the metric's `unit` is a percent unit) | `ms0` | integer milliseconds, converted from the sibling `unit` when it is `s`/`us` |
| `g` | grouped integer `65,810,000` | `nm3` | three decimals |
| `int` | integer, no grouping | `f1` / `f2` / `f3` | fixed decimals |

A pre-pass rewrites each placeholder into `{{ q("rel.json", "jsonpath", "fmt") }}`
before Jinja parses the template (line numbers are kept). `q()` emits the text
plus a marker `<!--src:results/sealed/v1.json#metrics['top1.pooled'].value q fmt=pct-->`
that `check_claims` re-renders exactly like an `m()` marker. `q()` adds **no**
DEV/SEALED label (the prose carries the context), but the DEV-in-a-sealed-sentence
rule still applies to it through the source file's `dataset`.

- **Inline code.** A placeholder that is the whole code span (`` `{{ x.json | k }}` ``)
  is rendered as `` `value` `` with the marker after the closing backtick (marker
  option `code`), so the marker never shows. A placeholder inside a larger code
  span is a render error.
- **HTML comments are emitted verbatim.** One that contains `{{`, `{%` or `{#`
  (such as the grammar description in A's header comment) is wrapped in
  `{% raw %}` by the pre-pass, so Jinja never evaluates text inside an HTML comment.
- A string value that spans lines or contains a comment delimiter, a JSON
  object/array, a `null`, or a number under a bad `fmt` is a render error naming
  the template line.

### Plain JSON documents under `results/`

A `results/**/*.json` file with no `metrics` key and a `schema_id` that is not
`driftsense.results/*` (for example `sealed/decisions.json` and
`sealed/disclosures.json` written by `eval/sealed_run.py`) is a **plain document**:
it must parse as JSON, is not validated as a `ResultsFile`, cannot be used with
`m()`, and is read with `q()` and the JSON logic helpers below. A file that looks
like a `ResultsFile` (has `metrics` or a results `schema_id`) but fails validation
is still an error (CL009). `requires:` accepts plain documents too.

## Logic helpers (never print numbers)

Templates sometimes need to branch on results: say "no measurable difference"
when a CI contains parity, show a row only if an optional arm exists, loop over
per-op metrics. These helpers do that without ever printing a number:

| Helper | Returns |
|---|---|
| `has(key)` / `has(key, metric)` | `true` if the results file (and metric) exists; never errors |
| `metrics(key, prefix="")` | sorted metric names starting with `prefix` (names, not values) |
| `ci_verdict(key, metric, null=1.0)` | `"higher"` (ci_low > null), `"lower"` (ci_high < null), `"includes"` (CI contains null: say *no measurable difference*), `"no_ci"` (no interval, or ci_low == ci_high, e.g. a single throughput run) |
| `exists(key_or_relpath, jsonpath=None)` | `true` if the results file (any JSON) exists and, if given, the path resolves; never errors |
| `flag(relpath, jsonpath)` | a JSON boolean as `True`/`False`, `None` for JSON `null` (an undecided rule); anything else is an error |
| `keys(relpath, jsonpath=None)` | the keys of a JSON object (rule IDs), or `"0"`, `"1"`, … for an array; names, never values |
| `kind(relpath, jsonpath)` | `object`, `array`, `string`, `number`, `bool`, `null` or `missing`, for branching |
| `val(key, metric, field="value")` | an opaque number for comparisons and truthiness only (`val(k, "x.pass")`, `val(k, "x") > 1`); `field` is `value`/`ci_low`/`ci_high`/`n`. Printing it (`{{ val(...) }}`) is a render error, so printed numbers always go through `m()`/`n()` |

```jinja
{% set v = ci_verdict("bench/cool_bench", "speedup.graviton-cool_vs_graviton-pip.kleidicv.geomean.tN") %}
{% if v == "higher" %}COOL is faster{% elif v == "lower" %}COOL is slower{% else %}no measurable difference{% endif %}:
{{ m("bench/cool_bench", "speedup.graviton-cool_vs_graviton-pip.kleidicv.geomean.tN", fmt="x", ci=true) }}
{% for name in metrics("bench/cool_bench", "cost.") if name.endswith(".usd_per_1000") %}...{% endfor %}
```

Never hard-code a conclusion ("COOL is faster") in prose: derive it from
`ci_verdict()`. With `--allow-missing`, missing data makes `has()` false,
`metrics()` empty, `ci_verdict()` `"no_ci"` and `val()` falsy.

## Sidecar files (`*_meta.json`)

Files under `results/` whose name ends in `_meta.json` (for example
`results/bench/cool_bench_meta.json`, written by `bench/cool/report.py` next to
`cool_bench.json`) are evidence sidecars: they must be valid JSON but are not
`ResultsFile`s, are not validated against the contract and cannot be used with
`m()`. Every other `results/**/*.json` must validate.

## Formats (`fmt=`)

| fmt | Input | Output example | Rule |
|---|---|---|---|
| `raw` | any | `12.3456` | shortest exact repr; integral floats print without `.0` |
| `int` | any | `1,234` | rounded, thousands separators |
| `f1` / `f2` / `f3` | any | `12.3` / `12.35` / `12.346` | fixed decimals |
| `pct` | fraction 0–1 | `47.5%` | ×100, one decimal; if `unit` is `%`/`percent`/`pct` the value is already a percentage and is not multiplied |
| `ms` | unit `ms`, `s`, `sec`, `us`, `µs` | `23.5 ms` | converted to ms; no decimals if ≥ 100, one if ≥ 10, else two; any other unit is an error |
| `x` | speed-up ratio | `12.3×`, `2.50×`, `1.045×` | one decimal if ≥ 10, two if ≥ 2, else three |
| `usd` | dollars | `$1,234.50`, `$0.432`, `$0.000119` | two decimals if ≥ 1, else three significant figures (at least two decimals) |

If `fmt` is omitted it is inferred from `Metric.unit`: `ms`→`ms`; `x`/`×`/`speedup`→`x`;
`usd`/`$`→`usd`; `%`/`percent`/`fraction`/`ratio`/`rate`/`proportion`→`pct`;
`count`/`n`→`int`; anything else→`raw`. Pass `fmt` explicitly in reports.

With `ci=true` the 95% interval from `ci_low`/`ci_high` is appended with the
same precision as the value: `47.5% (95% CI 40.1–54.9%)`, `23.5 ms (95% CI 22.9–24.1 ms)`,
`12.3× (95% CI 11.0–13.5×)`, `$0.0123 (95% CI $0.0100–$0.0150)`. A metric without
both bounds is an error. The level is always 95% (Wilson for rates, bootstrap
for timings, per the evaluation protocol).

Units that are not a format (nm, px, jobs per hour) go in the surrounding text
or the table header: `{{ m("sealed/finfet", "subpixel_err_nm", fmt="f2") }} nm`.

## DEV / SEALED labels

- A number from a file with `dataset="dev"` automatically gets ` [DEV]`;
  `dataset="sealed"` gets ` [SEALED]`; `synthetic` and `bench` get no label.
- `label=false` drops the label (use it in a table whose caption already says
  which split it is). Never drop it to hide that a number is DEV.
- A DEV number in the same sentence as the word "sealed" (any case, including
  another number's `[SEALED]` label) **fails the render** and fails
  `check_claims` (code CL005). Sentences are split at `.`/`!`/`?` followed by
  whitespace; each table cell, heading and list item is its own unit. Keep DEV
  and SEALED numbers in separate sentences or table cells.

## Errors you will see

- `docs/templates/X.md.j2:12: results key 'accuracy/g9' -> results/accuracy/g9.json not found`:
  wrong key, or the producing script has not run yet.
- `docs/templates/X.md.j2:12: metric 'speedupp' not in results/accuracy/g2.json (available: ...)`.
- `docs/templates/X.md.j2:7: undefined: 'foo' is undefined`: templates use
  `StrictUndefined`; any unknown variable is an error.
- `results/accuracy/g2.json: invalid ResultsFile: ...`: every `results/**/*.json`
  must validate, or nothing renders.

## Waiting for results: `requires`

A template may declare the results it needs in a Jinja comment:

```jinja
{#- requires: bench/cool_bench sealed/finfet -#}
```

If any listed file is missing, the template is **PENDING**: it is skipped with a
message, not rendered, and `make docs` still succeeds (`--strict` turns pending
into a failure; use it at numbers-lock). A key used in the template but not
declared, or a declared file that exists but lacks the metric, is a hard error.
`check_claims` warns (CL011) about pending templates without output, and errors
(CL008) if a pending template still has an old generated file on disk.

## Policy constants are words, not numbers

Retention days, dose budget and agent step cap are configuration, not measured
results, and `ResultsFile.dataset` has no `config` value. They are written in
words in templates (for example, "kept for seven days") and must match their
single source of truth (infra S3 lifecycle rule; agent safety config). The
reviewer checks that match at numbers-lock. Measured numbers must always come
from `m()`.

## Template rules of thumb

- Templates render with `trim_blocks` and `lstrip_blocks`, so `{% %}` lines leave
  no blank lines. Output always ends with exactly one newline.
- Never call `m()`/`n()`/`meta()` inside a fenced code block or a Mermaid diagram:
  the marker would show literally (check_claims code CL010).
- Never write raw values (there is no `results` variable on purpose; `val()` is
  for logic only and refuses to print).
- Prefer words for small structural counts ("three diagrams"); single digits are
  not treated as claims, but anything else may be.

## What check_claims enforces

It scans `docs/**/*.md` (except `docs/templates/`), `README.md` and
`SUBMISSION.md`. Files with the GENERATED header are checked strictly
(errors, exit 1); all other markdown is **legacy** and only gets warnings
(exit 0) unless `--strict-legacy`. A non-generated file whose first line is
`<!-- check_claims: skip (reason) -->` is not scanned (this file uses it because
its numbers are syntax examples); the opt-out cannot apply to generated files,
whose first line is always the GENERATED header. If no generated docs exist yet it prints
`no generated docs yet` and exits 0 (legacy warnings are still printed).
Output is `path:line: CODE message`; `--json` gives machine output.

| Code | Rule |
|---|---|
| CL001 | A digit-bearing claim with no provenance marker (see below) |
| CL002 | The text before a marker does not equal the value re-rendered from the JSON under the marker's `fmt`/`ci`/label |
| CL003 | A marker points to a results file or metric that does not exist, or is malformed |
| CL004 | The banned v1 metric name (recall at sixty, written with `@`); use `candidate_set_size` |
| CL005 | "sealed" in the same sentence as a DEV-sourced number |
| CL006 | A `⟨missing: ...⟩` placeholder |
| CL007 | Unfinished text: the to-do / to-be-decided words in capitals, or an `XX%` placeholder |
| CL008 | Stale render (a fresh in-memory render differs from disk), not rendered yet, or orphaned generated file; skip with `--no-render-check` |
| CL009 | A `results/**/*.json` file that does not validate as `ResultsFile` |
| CL010 | A marker inside a code block |
| CL011 | (warning) a template is pending because its results do not exist yet |
| CL012 | A template syntax or render error |

**What counts as a claim (CL001).** The text is first cleaned: provenance-marked
values, HTML comments, fenced code blocks, inline code spans, URLs, link
targets and HTML tags are removed. Each remaining whitespace-separated token
that contains a digit is a claim if it has a unit or currency (`%`, `×`, `x`,
`ms`, `s`, `nm`, `px`, `µs`, `us`, `ns`, `k`, `GB`, `MB`, `KB`, `h`, `min`, `fps`,
`$`), is followed by a unit word (`ms`, `seconds`, `nm`, `px`, `pixels`,
`minutes`, `hours`, `days`, `GB`, …), has a decimal point or exponent, or has
two or more digits in a row (so `200`, `1,000`, `10⁶`, `1000×1000` are claims).
A lone single digit without a unit (`OpenCV 5`, `3 diagrams`) is not.

**Allow-list (never claims):**

- Dates and times: `2026-10-26`, `2026-10-26T12:00Z`, `2026/10/26`, `21:00`,
  `0:00–0:20`; a four-digit year from 1900 to 2099 (unless a unit word follows);
  a day number next to a month name (`Oct 26`, `11–26 Oct`).
- Versions: three or more dotted parts (`5.0.0.93`), `v`-prefixed (`v2`, `v1.0`),
  or a dotted number right after a product word such as OpenCV, Python, COOL,
  Node, CUDA, Ubuntu, NumPy, pydantic, Jinja2, CDK, KleidiCV, TLS, Graviton,
  Industry (`Python 3.12`, `Python 3.10+`, `COOL 3.1`).
- Identifiers: any token with letters glued to digits that are not a unit
  (`c8g.large`, `m8g.4xlarge`, `S0–S9`, `p95`, `x86`, `arm64`, `top-1`,
  `ap-south-1`, `sha256`).
- Structure: a number after a section word (Prompt, Section, Step, Phase, Gate,
  Stage, Figure, Table, Appendix, Day, Rule, Level, Item, Issue, PR, Part,
  Chapter, Task, Line, Page, Row, Column, Priority, Week), `§10`, issue refs
  `#123`, citation refs `[12]`, numbered headings (`## 10. Report`) and
  numbered list items.
- Nomenclature: `95%` directly followed by `CI` (the interval level fixed by the
  protocol). Stage labels `S0–S9`, engine names `v1`/`v2`, rule and gate IDs
  (`D1–D12`, `G2`), `recall@K`, `arm64`/`amd64`, tags such as `v1-munichtech`
  and dated disclosure IDs are already identifiers (letters glued to digits),
  `OpenCV 5` is a product version, and `5.0.0.93`-style versions match the
  version rule. This list is deliberately short: every other digit in prose
  must come from a marker.
- Anything inside fenced code, inline code, HTML comments, URLs and link
  targets. (Do not abuse this: code spans are for code, not results.)

The exact regular expressions live in `scripts/check_claims.py`; if a legitimate
non-claim is flagged, extend the allow-list there with a test, never hand-mark it.
